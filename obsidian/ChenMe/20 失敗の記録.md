# 失敗の記録

やり直しになった判断と、その根本原因。同じ轍を踏まないためのもの。
**「何を間違えたか」より「なぜそう判断したか」を書く。**

## スコープを勝手に狭めた

**症状**：施主が「イラストは変えられない」と言ったのを、キャラ含む全素材に
拡大解釈した。その結果、キャラを2Dの板→切り絵パペットと二段階で作り、
どちらも「アニメっぽくない」と却下された。3回目にようやく
「変えたら行けないのは4枚目のボトルだけ」と明示された。

**根本原因**：制約の**範囲**を確認せずに、安全側に倒して勝手に狭めた。

**次回の初手**：
> 「変えてはいけないのはどれですか。キャラは作り直していいですか」
> を、着手前に1行で聞く。

---

## 3Dで作り直したら「可愛くない」で全却下（最大の失敗）

**症状**：「ピクサー並みに」と言われて、キャラを3Dジオメトリから作り直した。
寸法は参照画像を実測して合わせ、ターンアラウンドも成立し、カメラも回り込めた。
それでも一言、「当初の画像とかけ離れすぎている。可愛くない。2Dで構わない」。

**根本原因**：施主が守りたかったのは「回り込める立体」ではなく
**「元の絵の可愛さそのもの」**だった。プリミティブで組んだ顔は、
比率が合っていても元のレンダーの質感・線・表情の"抜け"を再現できない。
「ピクサー並み」は**動きの質**への要求であって、3D化の要求ではなかった。

**教訓**：
> 「元の絵のピクセルをそのまま使う」ことが可愛さの担保。
> 動きの質は**2Dパペット＋オーバーラップ層**で出す。3Dに逃げない。
> 施主の形容詞（ピクサー並み）を手段（3D）に翻訳する前に、
> 「動きの話ですか、立体の話ですか」を1行で確認する。

**結果**：2Dパペット（元ピクセル）＋遅れ・バネの層＋ポンポン＋120fpsブラーで、
「これでいい」になった。3Dに費やした時間はまるごと回り道。

## 板 → パペット → 3D → パペット の回り道

| 版 | 実装 | 却下理由 |
|---|---|---|
| v1 | 1枚の板にポーズ画像 | 「絵が跳ねてるだけ」 |
| v2 | 素材を関節パーツに切って2Dパペット | 「まだアニメっぽくない」 |
| v3 | 3Dモデル＋スケルトン | 「可愛くない」「かけ離れすぎ」 |
| **v4** | **2Dパペット（元ピクセル）＋オーバーラップ層** | **採用** |

**根本原因**：v1→v2 は「素材を変えない」に縛られて板を動かし続けたこと。
v2→v3 は逆に、「動きの質」の要求を「3D化」に翻訳してしまったこと。
正解は v2 の骨格に v3 で作った**オーバーラップ層**を乗せることだった。
つまり足りなかったのは造形の次元数ではなく、**追従の遅れと揺り戻し**。

**教訓**：
> 要求が手段の上限を超えていると気づいた時点で、作る前に言う。
> 「この方法だとここが上限です。超えるにはXが必要です」と1回で伝える。

## AI生成ポーズは連番アニメにならない

Gemini image で8ポーズを生成 → 連続再生してアニメにしようとした。
生成ごとにサイズ・色・ディテールが微妙に違うため、繋ぐと画面が沸騰する。

**使える用途**：単発の差分ポーズ、表情差分（カットが変わる箇所）
**使えない用途**：走りサイクル、跳躍などの連続運動

## 造形の数値を目分量で置いた

キャラを3D化するとき、寸法を「だいたいこのくらい」で置いて何度もやり直した。
最終的に**参照画像のシルエットを1行ずつ実測**して一発で合った。

```python
# これを最初にやる
a = np.array(Image.open(ref).convert('RGBA'))[:,:,3] > 128
for y in range(0, H, 20):
    xs = np.nonzero(a[y])[0]
    print(y, xs.min(), xs.max())   # 各高さの幅が出る
```

**教訓**：造形は最初に実測する。目分量は必ず3往復以上に化ける。

## 「丸々しすぎ」の正体は2つ

施主の「丸々しすぎ」は感覚的な指摘だったが、実測すると原因は明確だった。

1. **手足が太い**：参照は腕＝顔幅の12.7%、脚＝10.9%。
   作ったものは19.6% / 20.0%。**倍近く太かった**
2. **顔に対してフードが大きい**：参照のフードは顔の1.12倍幅の薄いキャップで、
   顎はフードの下から出ている。球殻で作ると「ボール」になる

**教訓**：主観的な形容詞（丸い・ダサい・かわいくない）が来たら、
参照画像を**比率で実測**して数値の差に翻訳する。

## テクスチャの上下が反転していた

`patchGeometry` の UV を `1 - j/NV` にしていたため、顔テクスチャが上下逆に
貼られ、「眉が下・チークが上」の顔になっていた。気づくのに数往復かかった。

**チェック手順**：非対称なテクスチャ（顔・ラベル）を貼ったら、
**貼った直後に1枚レンダーして向きを確認**してから次に進む。

---

## 三角形の巻き方向を毎回間違える

自前 BufferGeometry を書くたびに `idx.push(a,c,b, b,c,d)` と
`idx.push(a,b,c, b,d,c)` のどちらが表かを間違えて、
「メッシュが消える」「暗くなる（法線が内向き）」を繰り返した。

**対処**：新規ジオメトリは必ず `side: THREE.DoubleSide` で先に出す →
表示されたら巻き方向を確定して FrontSide に戻す。

## 並行プロセスが成果物を壊す

前セッションの ffmpeg が生き残っていて、同じ出力ファイルに同時書き込みし、
`moov atom not found` の壊れたmp4ができた。

**対処**：長時間ジョブの前に `pgrep -a ffmpeg` / `pgrep -f render3d` で確認。
待機は `until [ -z "$(pgrep -f ...)" ]; do sleep N; done`。

## 潰しを効かせすぎると3Dでは壊れる

着地の squash を -0.46 にしたら、3Dモデルだと完全な円盤になって
「バグ」に見えた。2Dの板では成立していた値。

**目安**：3Dでは squash の下限 **-0.30** 程度。伸びは +0.24 まで。
