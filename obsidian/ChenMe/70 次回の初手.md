# 次回の初手

この案件、または似た「支給素材でキャラ動画を作る」案件を受けたときの手順。
**最初の30分でここを全部潰す。** 潰さずに作り始めると必ず往復が増える。

## 0. キャラは元ピクセルの2Dパペットで作る（結論）

3Dに作り直さない。可愛さは元の絵にしか無い。
`handoff/cut_parts.py` でパーツを切り、`render/lib/puppet.js` で骨を入れ、
`scene3d.html` のオーバーラップ層で動かす。これが到達点。
→ [[20 失敗の記録#3Dで作り直したら「可愛くない」で全却下（最大の失敗）]]

「ピクサー並みに」と言われたら、それは**動きの質**の話。
遅れ・揺り戻し・予備動作・潰し伸ばし・ポンポン等の二次運動で応える。

## 0.5 施主が「このくらい」と動画を渡してきたら、フレームを並べる

`ffmpeg -vf fps=2` で30枚抜いてシートにする。全編生成なら、その
キーフレームを seed にしてラベル差し替え（`handoff/make_ref_plates.py`）
→ Veo（`handoff/veo_generate.py`）→ `handoff/assemble_ref.sh`。
本物ボトルは `handoff/product_end.py` で最後に被せるだけ。

## 1. スコープを1行で確定させる

> 「変えてはいけない素材はどれですか。キャラクターは作り直していいですか」

- 答えが「イラストだけ」→ キャラは**元ピクセルのパーツ切り出しパペット**。3Dにしない
- 答えが「全部そのまま（切り出しも不可）」→ **動きの上限をその場で伝える**。
  「1枚板の合成になるので、手足は動きません。動かすにはパーツ切り出しの許可が要ります」

→ [[20 失敗の記録#スコープを勝手に狭めた]]

## 2. 参照画像を実測する

目分量で置かない。最初に数値にする。

```python
from PIL import Image; import numpy as np
a = np.array(Image.open(ref).convert('RGBA'))[:,:,3] > 128
for y in range(0, a.shape[0], 20):
    xs = np.nonzero(a[y])[0]
    if len(xs): print(y, xs.min(), xs.max(), xs.max()-xs.min())
```

出す比率：**腕の太さ／脚の太さ／胴幅／フード幅／顔のアスペクト**（÷顔幅）
→ [[40 キャラクター仕様#比率]]

## 3. 制約を実装で担保する

- 目を開けない → 開いた目を描く関数を**作らない**
- 製品画像を変えない → 生成にもマテリアルにも**通さない**。`<img>` 合成のみ

## 4. 骨格を先に組んでポーズシートを1枚出す

芝居を書く前に、`turn`（正面→3/4→真横→背面）と
`pose`（代表6ポーズ）のシートを出して**施主に見せる**。
ここで形が合っていないまま芝居を作ると、全部やり直しになる。

## 5. 動きはオーバーラップ層で作る

意図（`charXform`）と追従（`drag`/`ring`）を分ける。
手付けで遅れを作らない。→ [[50 アニメーション設計]]

## 6. レンダー前のチェックリスト

- [ ] `pgrep -a ffmpeg` / `pgrep -f render3d` が空か
- [ ] 非対称テクスチャの上下は合っているか（貼った直後に1枚確認済みか）
- [ ] squash の下限が −0.30 を超えていないか
- [ ] 9:16 で横が切れていないか（three.js の fov は垂直）
- [ ] 所要時間の見積もりを施主に伝えたか（60fps 24秒 ≒ 30分）

## 7. 出すもの

本編 mp4 に加えて、**動きが分かる素材**を必ず添える。

- 連続コマのストリップ（着地・走り・カメラの回り込み）
- 短いGIF（3秒程度）
- ターンアラウンドのPNG

静止画のコンタクトシートだけだと「動きがどうか」が伝わらない。
