# レンダリング環境

## 構成

```
three.js (WebGL2)  →  headless Chromium (SwiftShader / ソフトウェア描画)
                   →  Playwright で1フレームずつ screenshot
                   →  ffmpeg で結合
```

GPUなし。**SwiftShaderのソフトウェア描画**なので重い。
Chromium 起動フラグ：

```
--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader
--ignore-gpu-blocklist --force-device-scale-factor=1 --hide-scrollbars
--force-color-profile=srgb --disable-lcd-text --font-render-hinting=none
--js-flags=--max-old-space-size=3072
```

## 所要時間の実測（1080×1920）

| 構成 | 秒/フレーム | 24秒尺の総時間 |
|---|---|---|
| 2Dパペット（板） | 0.75 | 30fps: 9分 / 60fps: 18分 |
| 3Dモデル＋影 | 1.25–1.45 | 60fps: 29分 / **120fps: 65分** |

> [!tip] 見積もりの目安
> 3Dモデルで 60fps 24秒 ≒ **30分**。120fps なら **65分**。
> 部分修正は `--from/--to` で数分。

## エンコード

```bash
# 通常（60fps）
ffmpeg -y -framerate 60 -i frames3d/f%05d.jpg -i audio/score.wav \
  -c:v libx264 -preset slow -crf 18 -pix_fmt yuv420p \
  -profile:v high -level 4.2 -c:a aac -b:a 192k -shortest \
  -movflags +faststart out.mp4

# モーションブラー付き（120fps素材 → 2枚平均 → 60fps）
ffmpeg -y -framerate 120 -i frames3d/f%05d.jpg -i audio/score.wav \
  -vf "tblend=average,framestep=2" -r 60 \
  -c:v libx264 -preset slow -crf 18 -pix_fmt yuv420p ... out.mp4
```

## 落とし穴

> [!danger] 並行プロセス
> 前のジョブの ffmpeg / node が生き残っていると出力を壊す。
> `moov atom not found` が出たら、まだ書き込み中か二重書き込み。
> ```bash
> pgrep -a ffmpeg; pgrep -f render3d
> until [ -z "$(pgrep -f 'ffmpeg')" ]; do sleep 20; done
> ```

> [!danger] ディスク
> 120fps 24秒 = 2880枚 ≒ 900MB。書き込み可能領域は固定枠なので
> `df` の Avail が 0 でも「壊れた」わけではない。不要ファイルを消せば戻る。

## ネットワーク

- 送信は agent proxy 経由。CA: `/root/.ccr/ca-bundle.crt`
- **Runway は 403（組織のegressポリシー）で到達不可**
- Vertex AI / Gemini API は到達可
- Vertex のモデルIDは `-001` 系（`veo-3.1-lite-generate-001`）。
  Gemini API 側の `-preview` 系とは別物
